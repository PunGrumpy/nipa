`nipa -p Beta server ls` now looks at another project for one run, without `nipa switch` changing the project every terminal uses. `-p, --project` takes a project name or ID, works before or after the command (and before `os`, `tf` and `exec`), beats a folder's link, and is never saved. nipa prints `Using project Beta`. A 32-character ID costs no extra request, and a project whose name looks like an ID still works. A name or ID that no project has exits with code 1 and lists your projects, and a name that two projects share fails and lists their IDs, in `login`, `switch` and `link` too, instead of picking the first. A revoked session under `-p` still says to run `nipa login`.

The commands nipa suggests in a hint, a note or a `--json` error, such as `nipa -p Beta server start db-1`, now keep your `-P` and `-p`, so copying them acts on the project you were looking at. `nipa -p Beta open` names Beta in the portal and fails for a project you don't have. `nipa login -p` still chooses the project to save. The commands that never read a project (`whoami`, `doctor`, `switch`, `link`, `unlink`, `logout` and `profile`) refuse `-p` with exit code 2 instead of ignoring it, so `nipa -p Beta switch Alpha` can't save a project by accident. Tab completion offers your project names after `-p` and finds the command after it, in bash, zsh, fish and PowerShell. `nipa exec -p Beta env` now says that nipa's options go before `exec`.
