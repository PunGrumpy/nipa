`nipa mcp` lets an AI assistant that you already use, such as Claude Code, Claude Desktop, Cursor or Codex, read your Nipa Cloud project with the session nipa saved, so it can help you find out why something is down. nipa holds no AI key and calls no model: the command runs a Model Context Protocol server on stdin and stdout, and you add it to the assistant, for example with `claude mcp add nipa -- nipa mcp`. It offers 17 tools that only read: they list and inspect servers, volumes, networks, security groups, load balancers (with a diagnosis of which part is down), databases, Kubernetes clusters, quotas and flavors, read the end of a server's console log and its history, and search servers in every project. Each returns the JSON that the matching command prints with `--json`. Nothing starts, stops, creates or deletes anything. `-P` and `-p` before `mcp` pick the profile and project for the whole run, and each tool takes a `project` of its own for one call, without saving it. nipa never prompts here: when the session expired, a tool returns an error that asks you to run `nipa login` in a terminal, and the next call works once you did. A failed tool returns the same message, reason and next commands as `--json`. Messages go to stderr, so stdout carries only protocol messages. Other commands don't start slower for it, apart from a few milliseconds for a larger package.
