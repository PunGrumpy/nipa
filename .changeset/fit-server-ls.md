`nipa server ls` now fits your terminal and works with `grep`. In a narrow terminal it drops the Flavor column, then Age, then shortens `(Kubernetes worker)` to `(worker)`, then prints each server as two lines, so rows no longer pile on each other and a name or address is never cut. In a pipe it now prints a header and one tab-separated line per server (ID, name, status, address, flavor and creation time as an ISO date), so `nipa server ls | grep web` filters the servers and stops printing the table on stderr. This changes what a pipe receives: it used to be one ID per line. To get the IDs, run `nipa server ls | tail -n +2 | cut -f1`, or `nipa server ls --json | jq -r '.servers[].id'`. Update any script that feeds this to `xargs`: it would read every field as a server name, and a script that picks a line by number now gets the next server. Pick the ID first, and match the name's own field before anything that stops a server, because `grep` searches every field and a short word can match an ID: `nipa server ls | awk -F'\t' '$2 ~ /^web/ {print $1}' | xargs -n1 nipa server stop --yes`.
