`nipa server search web` finds servers across every project you can use, so you no longer open them one by one. It matches a piece of a server's name, ID or any address, ignoring case, and treats the query as plain text. Without a query it lists every server. nipa asks each project live, four at a time, and saves nothing, so a server that the portal, Terraform or Kubernetes just made shows up. In a terminal, the matches sit under their project, the project `nipa server ls` shows is marked `(current)`, and a name that a project gives to two servers has each server's ID under it. When only one server matches, nipa prints the command to inspect it, such as `nipa -p Beta server inspect worker`, and the commands it suggests keep your `-P`. A folder's link doesn't narrow the search, and `nipa -p Beta server search web` searches only Beta. In a pipe, it prints a header and one tab-separated line per match (ID, name, project, status, address, flavor and creation time), so `nipa server search web | cut -f1,3` and `grep -i active` work. `--json` prints the matches with their `project`, how many projects it `searched` out of the `total`, and the projects that `failed`. When a project can't be read, because you aren't allowed to list its servers or it takes more than 15 seconds, nipa still prints the servers it found, says `in 4 of 6 projects` instead of claiming all of them, lists the projects it skipped and exits with code 1. With `--json` it prints its document and exits with code 1 without an error document. When your session expired, it prints that one error and tells you to log in.
